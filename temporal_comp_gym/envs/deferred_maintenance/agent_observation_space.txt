# Deferred Maintenance Task - Observation Space (protocol v2)

The agent receives a flattened 1D continuous array of observations at each time step. The environment is wrapped by `DeferredMaintenanceObservationWrapper` (in `wrappers.py`), which flattens the raw dictionary generated by `core.py` into the following structured vector (raw units; 25 values with `local_grid` and 3 code types). This is what a plain `gym.make("TemporalComp/DeferredMaintenance-v0")` returns.
The protocol v2 baselines see a rescaled 28-value version of it (see "Scaled observation used by the baselines").

## 1. Kinematics (6 values)
- `[0]` **pos_x**, `[1]` **pos_y**: position in the current stage (pixels; one cell = 50 px; y grows downwards).
  Each stage has its own coordinates, so the position jumps when a new stage starts.
- `[2]` **vel_x**, `[3]` **vel_y**: velocity (pixels/s).
- `[4]` **angle**: rotation angle (radians, limited to +/- pi/2).
- `[5]` **ang_vel**: angular velocity (radians/s).

## 2. Micro-Navigation Sensors (8 or 9 values)
- **`local_grid` (9 values, v2 baseline)**: the cell type of the 3x3 neighbourhood of the rocket's cell, row by row
  from top-left (the rocket's own cell is the middle value):
  `0` = empty void (or outside the stage), `2` = path (incl. collected code zones), `3` = code zone, `4` = station,
  `5` = exit, `6` = entry, `7` = stage boundary.
- **`raycasts` (8 values)**: fraction (0-1) of the ray length at which each of 8 rays (every 45 degrees, up to 150 px)
  first hits any shape other than the rocket; 1.0 if nothing is hit. Path tiles are shapes too, so this reads 0.0
  whenever the rocket's centre is on the path. Not used by the baselines.

## 3. Macro-Navigation Waypoint (2 values)
- Offset (dx, dy) in pixels from the rocket to the centre of the next path tile towards the exit
  (from the nearest path tile when the rocket is off the path).

## 4. Current Floor Code (1 value)
- `0.0`: not touching a station or code zone; otherwise the type id of the station (or, if none, the code zone) touched.

## 5. Action Readiness Indicator (1 value)
- `0.0` before readiness, `1.0` from the step on which the rocket enters the readiness stage until the episode ends.

## 6. Station Radar (2 values per code type)
- Offset (dx, dy) in pixels to the nearest station of each type in the current stage, or `[-99, -99]` if none exists
  (only possible with `distractor_stations=False`).

## Scaled observation used by the baselines
`MaintenanceScaledObservation` (applied by `agents/common/env_factory.py` for PPO, RecurrentPPO and PPO-RM)
rescales this to 28 values with fixed constants: positions and offsets in cells (/ 50), velocities / 200,
angle unchanged, angular velocity / 10, grid codes / 7, floor code / K, readiness unchanged, and the radar as
(present, dx, dy) per type instead of the -99 sentinel (absent -> 0, 0, 0).

## Actions
Box(2,) in [-1, 1]. `[0]`: thrust along the nose (force 2000 x value) when positive; air brake (zero horizontal
velocity and spin, once per press) when it first drops below -0.5. `[1]`: rotation torque; at |value| <= 0.05 the
rocket levels itself. One step = 1/60 s of simulated time.

## Episode structure (protocol v2)
- A seeded schedule is drawn at reset: readiness stage r in `readiness_delay_range` (inclusive, default 1-2),
  and one distinct code type per stage before r. Codes appear only in those stages.
- Every stage has one station per station type: the issued types, plus all other types when
  `distractor_stations=True` (v2 main condition; the code default is False). The station layout never depends on the held codes.
- A perfect run is therefore always possible: collect every code, service each one once ready, exit the last stage.
- Servicing: overlap a station for 2.0 s (120 steps). +100 if ready and the code is held, -10 if not yet ready,
  -10 if ready but the code is not held. Staying longer repeats the attempt every 120 steps.
- Exiting a stage with an uncollected code ends the episode (-1000). Exiting the last stage ends it:
  +1000 if no codes are held (success), -1000 otherwise.
- Per-step penalties: -5 while touching a stage boundary, -0.1 while the rocket's centre is over a void cell.
- `max_steps=4000` truncates the episode (the oracle's p95 length is ~1,860 steps).

## Info dictionary (protocol v2)
- `info["events"]`: `code_collected(k)`, `boundary_contact`, `service_attempt(k)` (hover timer reached),
  `off_path`, `stage_exit(s)` / `stage_exit_incomplete(s)`, then `readiness_on` or `final_exit`, in processing order.
  Reset returns an empty list.
- On the last step: `info["termination_cause"]` (`success`, `uncollected_codes_at_exit`,
  `held_codes_at_final_exit`, `timeout`) and `info["is_success"]`.
- `info["debug"]` (held/serviced/issued codes, readiness target, stage, uncollected codes) only when `debug_info=True`.
